## Customization Checklist for Each Role

### Step 1: Pick the Right Resume Version
- [ ] Identify role tier (1 = enterprise scale, 2 = security, 3 = distributed, 4 = hardware)
- [ ] Select corresponding resume file
- [ ] Make a copy with role name: `RESUME_GOOGLE_TECHNICAL_LEAD.md` (helps stay organized)

### Step 2: Customize PROFESSIONAL SUMMARY (1 paragraph)
- [ ] Replace generic language with role-specific terms
- [ ] Emphasize key competencies for this role (use ARCHITECTURE_ROLES_POSITIONING.md as reference)
- [ ] Keep 4-5 sentences; scannable in 10 seconds
- Example for Google: "Senior systems architect with expertise in **infrastructure-scale** information architecture, **cloud-quantum integration**, and **policy-as-code frameworks**..."

### Step 3: Customize Cover Letter (Starting Point)
- [ ] Use template from ARCHITECTURE_TRACK_PLAN.md
- [ ] Identify company's specific challenge (from job description)
- [ ] Connect 5-layer model (or 6-stage loop) to their challenge
- [ ] Reference specific code sections (line numbers)
- [ ] Keep to 4-5 paragraphs; 1-2 min read

### Step 4: Prepare Interview Talking Points
- [ ] Read INTERVIEW FOCUS section at bottom of resume
- [ ] Practice 5-minute pitch for main talking point (5-layer model, 6-stage loop, constraint engine, policy framework, or layer contracts)
- [ ] Prepare to draw on whiteboard (5-layer model, 6-stage loop, distributed architecture)
- [ ] Memorize 2-3 code references with line numbers
- [ ] Prepare 3 follow-up questions to ask interviewer

### Step 5: Submit Application
- [ ] Update resume with customized PROFESSIONAL SUMMARY
- [ ] Write cover letter (customize based on company challenge)
- [ ] Proofread (spelling, grammar, role name matches job description)
- [ ] Save with naming convention: `RESUME_COMPANY_ROLE.md` for your records
- [ ] Submit via job portal or LinkedIn (convert to PDF if required)

## Interview Preparation by Resume Type

### Enterprise Scale Resumes (Google, AWS TPM)
- **Preparation time**: 4-5 days (customize summary, write cover letter, practice pitch)
- **Whiteboard exercise**: Draw 5-layer model; map to company's specific infrastructure
- **Talking point**: Start with 5-layer model and team separation patterns
- **Code references**: quantum_schema.py, quantum_constraints.py, quantum_dashboard.py
- **Key message**: "I architect for organizations, not just systems"

### Principal/Staff Resumes (Atom, PsiQuantum)
- **Preparation time**: 4-5 days (customize for hardware type, practice loop explanation)
- **Whiteboard exercise**: Draw 6-stage loop; walk through with hardware-specific examples
- **Talking point**: Start with 6-stage feedback loop and real-time timing domains
- **Code references**: quantum_controller.py, quantum_constraints.py, quantum_simulator.py
- **Key message**: "I design for physics constraints and real-time determinism"

### Security/Governance Resumes (AWS/IBM Security)
- **Preparation time**: 3-4 days (customize for standards, practice policy flow)
- **Whiteboard exercise**: Draw governance layer; walk through policy decision flow
- **Talking point**: Start with governance layer and policy-as-code framework
- **Code references**: quantum_constraints.py, quantum_dashboard.py, quantum_controller.py
- **Key message**: "I make governance a first-class architecture layer"

### Distributed Systems Resumes (Qiskit, IonQ)
- **Preparation time**: 4-5 days (customize for compilation or networking)
- **Whiteboard exercise**: Draw 5 layers with multiple devices; explain networking at workflow layer
- **Talking point**: Start with layer contracts and independent evolution
- **Code references**: quantum_schema.py, quantum_controller.py
- **Key message**: "I design for independent teams and distributed scaling"

## Final Notes

- **Same Phase 1 code**: All resumes reference the same project; they're positioning angles, not different work
- **Different strengths**: Enterprise role emphasizes team scale; Principal role emphasizes real-time control; Security role emphasizes governance; Distributed role emphasizes contracts
- **Interview consistency**: Your Phase 1 implementation supports all these angles; just lead with the relevant one
- **Version control**: Keep both the base template (RESUME_ENTERPRISE_SCALE.md, etc.) and customized versions
- **Feedback**: After each interview, note what resonated and what didn't; adjust future customizations accordingly
